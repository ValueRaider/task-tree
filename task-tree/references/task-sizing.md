# Sizing Work for the Context Window

Size the work to be attempted before the next durable stopping point, not the
whole objective represented by a parent task. This applies to research, design,
implementation, review, and other substantive work alike.

Before starting, consider the context needed to understand the inputs, do the
work, verify the result, and record the handoff. Allow room for uncertainty and
findings that require revisiting earlier material; do not budget only for the
main action. File or line count alone is not a reliable workload estimate.

Identify a concrete stopping point and the evidence or artifact to preserve
there. If reaching it comfortably within the available context is doubtful,
add ordered children directly under the task for smaller portions of work.
Keep the overall purpose and completion criteria on the enclosing task; put
each child's scope and resume information on that child. Existing children do
not prevent adding further children where needed.

Choose boundaries that reduce how much context must be held at once and leave
a usable result for the next task. An independently checkable output can be a
useful boundary, but neither every new decision nor every separate test
requires a task of its own. No fixed software-stage template is required.

Reassess when unexpected investigation, repeated rereading, expanded scope,
or validation work consumes the room reserved for finishing. Record what is
known and split the remaining work before that room is exhausted. Preserve
completed work and make the next action explicit; do not attempt to finish an
oversized task merely because its handoff could survive compaction.

Use task artifacts for detailed findings and the task body for the compact
plan and resume state, following the skill's existing handoff rules. A parent
may span many context windows; its individual work portions and closeout need
the same sizing assessment as other work.
